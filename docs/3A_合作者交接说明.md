## 1. 当前进度与研究范围

**当前已实现 3A 的成对视图、交互、Pareto 计算和演示数据验证；尚未完成真实调度实验结果接入、3A/3B 集成及正式算法比较。**

默认页面中的“手工放置 A～G”是根据两任务样例构造的七种固定放置，用于检查指标、支配关系和选择事件。它们不是 Random、Latency-first、Energy-first、Balanced 或 DQN 的运行结果，不可作为算法性能证据，也不能通过改标签变成正式实验数据。

当前修订提案第 5.3 节规定的候选集合如下：

| 方法族 | 配置 | 数量 |
| --- | --- | ---: |
| Random | 记录随机种子的随机节点选择 | 1 |
| Latency-first | 最小化当前队列下预计端到端完成时间 | 1 |
| Energy-first | 最小化预计增量计算与传输能耗 | 1 |
| Balanced | 等权、偏重 makespan、偏重 energy | 3 |
| DQN | 一个固定 checkpoint，冻结推理 | 1 |
| 合计 | 六个启发式配置和一个学习策略 | 7 |

三个 Balanced 设置属于同一方法族；三张成对图表示三个目标组合，不代表只比较三个算法。若双方另行缩减研究范围，应同步修改提案、行动计划、manifest、完整性检查和测试。

当前阶段没有实现或训练 DQN，也没有开发完整模拟器。此前 3A 工作要求明确排除了这部分；提案中它们属于双方共同负责的 3C，仍需安排。

## 2. 已完成的功能

### 2.1 成对视图与交互

- 三张散点图：M–E、M–L、E–L；一个点对应同一 `instance_id` 下一个完整运行。
- 坐标单位：`makespan_s` 为秒、`energy_j` 为焦耳、`mean_latency_s` 为秒；全部最小化。
- 配置颜色和形状由完整配置列表中的 `policy_config_id` 排序确定；改变 manifest 数组顺序不会改变编码。
- 悬停显示配置名称、`run_id`、完整 M/E/L，以及该投影和完整三维的状态；选择后显示 `run_id` 标签。
- 点击、键盘 Enter/空格、Shift 追加选择、空白区域矩形 brush；三个现有视图同步高亮。
- 配置筛选、显式坐标范围修改、重置坐标、清除选择、选中记录 CSV 导出。

### 2.2 Pareto 与支配证据

- 三个二维投影和完整三维空间分别计算，使用原始数值和 manifest 容差。
- 完全相等的向量不互相支配；失败运行不生成目标点；混合实例的比较集合会被拒绝。
- 深色点描边表示当前二维投影非支配；金色虚线圈表示三维非支配；金色实线外圈表示选择状态。
- 详情区显示四组状态、双方完整指标、比较维度和各轴关系。
- 多个 witness 按 `run_id` 的 Unicode 码点字典序排序，首项为主要证据，其他有效证据 ID 同时列出。
- 视图筛选不会改变完整参照集合、Pareto 标签或默认轴域；未实现可见子集重算模式。

### 2.3 数据接入与检查

- 支持导入单实例 bundle，检查 ID 引用、任务数量、事件阶段、能耗及从事件重算的 M/E/L。
- Python 打包脚本读取归档文件，附上独立 Python Pareto 结果；浏览器核对 JavaScript 结果及 witness 内容。
- 原始 `examples/contract/` 数据未修改；演示数据保存在单独的 `examples/3a-demo/`。

## 5. 3B 如何复用散点图组件

### 5.1 调用约定

`drawPairScatter(svg, options)` 接受一个真实 SVG 元素。组件只绘制并返回选择事件，不拥有数据模型或共享状态。

| 参数 | 内容 |
| --- | --- |
| `runs` | 已校验的、当前实例中可见且 `status === "complete"` 的记录 |
| `xKey`、`yKey` | 指标字段名 |
| `xRange`、`yRange` | `{ min, max }`，要求 `min < max` |
| `selectedRunIds` | 共享状态中的选中 ID 数组 |
| `projectedLabels` | 当前投影的 `Map<run_id, classification>` |
| `fullLabels` | 完整三维的 `Map<run_id, classification>` |
| `axisLabels` | 按指标字段索引的轴标题，包含单位和最小化方向 |
| `encodeRun(run)` | 返回 `{ index, color }`，`index` 决定标记形状 |
| `tooltip(run, projected, full)` | 返回悬停文字；后两项为非支配布尔值或 `undefined` |
| `onSelect(runId, shift)` | 点击或键盘选择回调 |
| `onBrush(runIds, shift)` | 框选回调 |
| `formatValue(value)` | 坐标刻度的显示格式化函数 |

下面是拟放在 `app/3b/` 中的矩阵单元适配示例，不是当前已存在的 3B 文件。由共同入口提供通过 `readBundle()` 生成的 `model` 和唯一的 `sharedState`。

```js
import { drawPairScatter } from "../shared/pair_scatter.mjs";
import { POLICY_COLORS, stableConfigIndex } from "../shared/encoding.mjs";
import { PAIRS } from "../3a/pareto.mjs";

const axisLabels = {
  makespan_s: "总完成时间 M (s) ↓",
  energy_j: "任务相关能耗 E (J) ↓",
  mean_latency_s: "平均端到端延迟 L (s) ↓",
};

export function renderMatrixCell(container, model, sharedState, xKey, yKey) {
  const snapshot = sharedState.get();
  // PAIRS 只有三个规范方向；矩阵的反向单元使用同一组二维标签。
  const pair = PAIRS.find(([a, b]) =>
    (a === xKey && b === yKey) || (a === yKey && b === xKey));
  if (!pair) throw new Error("对角单元需要单独设计，不调用成对组件");

  // 每次渲染创建新的 SVG，避免在同一个元素上重复注册 brush 事件。
  const svg = document.createElementNS("http://www.w3.org/2000/svg", "svg");
  container.replaceChildren(svg);
  const choose = (ids, shift) => sharedState.selectRuns(
    shift ? [...sharedState.get().selected_run_ids, ...ids] : ids
  );
  drawPairScatter(svg, {
    runs: model.runs.filter(run =>
      run.instance_id === snapshot.current_instance_id &&
      run.status === "complete" &&
      snapshot.visible_policy_config_ids.includes(run.policy_config_id)),
    xKey, yKey,
    xRange: snapshot.axis_ranges[xKey],
    yRange: snapshot.axis_ranges[yKey],
    selectedRunIds: snapshot.selected_run_ids,
    projectedLabels: model.labels.pairs.get(pair.join("|")),
    fullLabels: model.labels.full,
    axisLabels,
    encodeRun: run => {
      const index = stableConfigIndex(model.configs, run.policy_config_id);
      return { index, color: POLICY_COLORS[index % POLICY_COLORS.length] };
    },
    tooltip: (run, projected, full) => {
      const status = value => value === undefined ? "未计算"
        : value ? "非支配" : "被支配";
      const config = model.configs.find(c => c.policy_config_id === run.policy_config_id);
      return `${config?.label ?? run.policy_config_id} | ${run.run_id}\n`
        + `M=${run.makespan_s} s, E=${run.energy_j} J, L=${run.mean_latency_s} s\n`
        + `二维：${status(projected)}；三维：${status(full)}`;
    },
    onSelect: (id, shift) => choose([id], shift),
    onBrush: choose,
    formatValue: value => Number(value.toPrecision(7)).toString(),
  });
}
```

### 5.2 集成注意事项

- 当前组件的 SVG viewBox 为 `600 × 390`，矩阵缩小后文字、标记和命中区域的可用性尚未验收。响应式尺寸或密集布局支持需实际检查后补充。
- SVG 依赖 `.grid`、`.axis`、`.tick`、`.axis-label`、`.brush` 等 CSS。首次集成可参照 `app/3a/style.css`；最终宜提取共享图表样式，避免直接导入整个页面样式导致布局冲突。
- 编码函数必须接收完整 `model.configs`，不能传筛选后的配置列表。增减配置集合可能改变排序槽位；跨不同 manifest 保持全局编码仍需约定固定映射。
- 图表只接收可见记录，但 Pareto 标签必须来自完整候选模型，不能对筛选后的 `runs` 重新调用分类函数。
- 相同投影坐标的点可能重叠。当前没有抖动或点展开功能；可用框选获得重叠点的多个 ID，再查看详情。最终需检查点遮挡和识别问题。
- 组件不代替数据校验，调用前使用 `readBundle()`。其他视图若采用不同绘图库，也必须返回真实 `run_id`，不能将数组下标当身份。

## 6. 共享状态如何接入

### 6.1 当前实现边界

`app/shared/state.mjs` 是浏览器内存中的发布/订阅对象。它沿用 `examples/contract/ui_state.json` 的字段语义，但**不会自动写回磁盘上的 JSON，不会自动跨浏览器标签或独立页面同步，也没有后端持久化**。

当前 `app/3a/app.mjs` 的 `state` 和 `model` 是模块内部变量，尚未向 3B 暴露。因此，3B 仅导入 `createViewState()` 并新建自己的状态对象，不会与现有 3A 联动。

建议双方将数据加载和状态创建提升到同一应用入口，再把同一个 `model`、同一个 `sharedState` 注入 3A/3B；不要直接导入 `app.mjs` 作为库，它包含页面初始化和控件事件绑定。

### 6.2 初始化示例

以下代码拟放在 `app/` 下的共同入口中：

```js
import { readBundle, defaultAxisRanges } from "./3a/model.mjs";
import { createViewState } from "./shared/state.mjs";

const response = await fetch("../examples/3a-demo/bundle.json");
if (!response.ok) throw new Error(`HTTP ${response.status}`);
let model = readBundle(await response.json());
const sharedState = createViewState({
  schema_version: "1.0.0",
  current_instance_id: model.instance.instance_id,
  selected_run_ids: [],
  visible_policy_config_ids: model.configs.map(c => c.policy_config_id),
  axis_ranges: defaultAxisRanges(model.runs),
  pareto_reference_run_ids: model.referenceStatus === "complete"
    ? model.referenceRuns.map(run => run.run_id) : [],
  pareto_reference_status: model.referenceStatus,
});
```

`fixture_only` 下正式参照 ID 列表为空，但完整七点演示数据仍可通过 `model.labels` 展示明确标注的演示分类。不要因此将它标成正式前沿。

### 6.3 API 与责任边界

| 方法 | 行为与注意事项 |
| --- | --- |
| `get()` | 返回状态副本；修改这个副本不会发布更新 |
| `subscribe(listener)` | 立即调用一次 listener，后续每次变更再调用；返回取消订阅函数 |
| `selectRuns(ids)` | 替换选中 ID 并去重；Shift 追加需要调用方先合并原选择 |
| `setVisibleConfigs(ids)` | 替换可见配置并去重；不修改选择、轴域或 Pareto 标签 |
| `setAxisRange(objective, range)` | 设置一个指标轴域；调用方检查字段名、有限值及 `min < max` |
| `changeInstance(instanceId, runIds, configIds, axisRanges, referenceIds, referenceStatus)` | 更新实例相关字段，并仅保留在新 `runIds` 中仍有效的选择 |

各视图通过 `subscribe()` 重绘，通过输入事件调用状态方法。**不要在订阅渲染函数中无条件调用状态写入方法**，否则可能递归触发更新。卸载视图时调用取消订阅函数。

当前状态层是轻量容器，`selectRuns()` 本身不验证 ID 是否属于当前实例；视图适配层必须从已校验模型取 ID。读取新实例时应先更新模型，再调用 `changeInstance()`，避免订阅者用新状态配旧数据。

建议平行坐标的轴 brush 首先作为选择操作：计算满足约束的运行 ID，调用 `selectRuns()`。如果设计成可见性筛选，需要双方另外定义其状态字段与清除规则；现有 `visible_policy_config_ids` 只表达配置可见性，不能表达任意运行子集。

3D 图点击同样调用 `selectRuns()`；旋转摄像机状态可由 3D 视图自己管理。三维的 Pareto 状态读取 `model.labels.full`，不根据摄像机角度重新计算。

## 7. 数据与 Pareto 对接规则

### 7.1 打包真实运行结果

生产端应按 `docs/data_contract.md` 生成冻结实例、manifest、运行记录和任务事件。所有配置重放同一个任务实例；失败记录保留失败原因，三个目标字段为 `null`，不得伪造数值点。

```sh
python scripts/build_3a_bundle.py --manifest path/to/experiment_manifest.json --instance-id INSTANCE_ID --output path/to/bundle.json
```

上述路径为占位符，替换为实验归档路径。manifest 的 `raw_data_paths.instances`、`raw_data_paths.runs` 以及各运行的 `event_log_path` 都按 manifest 所在目录解析。输出路径应与原始输入文件分开；脚本会写入指定输出文件。

bundle 包含 `schema_version`、`manifest`、`instance`、`runs`、`events` 和 `pareto_check`。页面右上角导入 bundle，或由共同入口加载它。不要跳过事件记录只提交三个汇总数字。

当前正式标签门槛是：非 fixture、manifest 声明七种配置、每配置恰好一个完整运行、同实例、Python 检查与 JavaScript 一致。少于七个完整候选时可以查看有效点，但不显示默认正式 Pareto 标签；这是当前实现的限制，不是 Pareto 数学上要求必须七个点。

当前导入校验不等于完整模拟器验证：FIFO 队列、可观察状态、禁止未来信息、checkpoint 来源等仍需 3C 的独立测试与归档证明。

### 7.2 标签结构

```js
const projected = model.labels.pairs.get("makespan_s|energy_j").get(runId);
const full = model.labels.full.get(runId);
// classification:
// { nonDominated, witnessRunIds, witnesses }
// witnesses[i]:
// { witnessRunId, comparedObjectives, targetMetrics, witnessMetrics, relations }
```

`relations` 的值为 `strict_improvement`、`equal` 或 `equivalent_within_tolerance`，描述 witness 相对目标运行在比较轴上的关系。主要 witness 不表示“最优算法”，只表示按固定规则选出的一个有效支配证据。

容差按每轴双方数值计算：`max(absolute, relative * max(abs(a), abs(b)))`。分类不使用显示舍入值。完全相同的向量不互相支配。

提案第 6.2 节关于“反向分类不可能”的句子需双方修订：A=(1,1,1)、B=(1,1,2) 时，三维 A 支配 B，但在前两个轴投影后二者相等，均可非支配。现有实现和测试遵循该形式定义，尚未修改原提案。
