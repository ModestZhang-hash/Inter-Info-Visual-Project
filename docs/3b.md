## 三种编码各自呈现什么

**散点图矩阵**复用 `app/shared/pair_scatter.mjs`。三行三列对应 `makespan_s`、`energy_j`、`mean_latency_s`。对角单元用文字写出轴名、单位和最小化方向，不调用散点图组件。非对角单元每次重绘都新建 SVG。反向单元与正向单元共用同一组二维标签，键为 `makespan_s|energy_j`、`makespan_s|mean_latency_s`、`energy_j|mean_latency_s`。它适合逐对查看 M–E、M–L、E–L。小单元沿用组件原有的 600×390 viewBox，再用 CSS 缩小；这一步没有修改 `pair_scatter.mjs`。

**平行坐标**把 M（秒）、E（焦耳）、L（秒）画成三条垂直轴，都标明最小化。每条完整且配置可见的运行是一条折线，颜色和形状字符来自完整 `model.configs` 上的 `stableConfigIndex()`。折线位置可以按当前坐标域归一化，归一化只用于绘制。悬停文字保留存储中的原始 M/E/L。它适合同时看三个目标的高低，轴上的刷选用来挑出落在某个原始值区间内的运行。

**简洁 3D** 使用无依赖 SVG 的固定斜投影，没有旋转控件，也没有引入 Three.js。画面横向主要对应 M，向上主要对应 E，斜向对应 L。投影参数固定为 `VIEW3D`：`depth = 0.55`，`angle = π/6`，先按当前坐标域把三个原始值归一化到绘图位置。金色虚线圈表示 `model.labels.full` 中的三维非支配。它适合看三个目标放在同一投影里时点的相对位置；固定视角会有遮挡，不能靠转动把点分开。

## 共享状态与选择

三种视图读取同一批已校验记录。点、折线的身份是 `run_id`，不是数组下标。配置颜色和形状槽位使用完整配置集合，不使用筛选后的配置列表。

选择、可见性和坐标只调用已有的 `selectRuns()`、`setVisibleConfigs()` 和 `setAxisRange()`。

- 筛选只替换 `visible_policy_config_ids`。它不改 `axis_ranges`、`pareto_reference_run_ids`，也不重算二维或三维标签。
- 「显示全部」把全部配置重新标为可见。它不选中这些运行。
- 「清除选择」调用 `selectRuns([])`。选中计数、高亮和详情会清空。点和折线仍留在图上，因为它们表示运行本身。
- 平行坐标的轴刷选范围只留在该模块内部。松手后，在当前可见且完整的运行里取落在范围内的 `run_id` 并调用 `selectRuns()`。多轴刷选取交集。它不调用 `setVisibleConfigs()` 或 `setAxisRange()`。
- 3D 点击一个点时，若其他可见点与它的投影距离不超过 `OVERLAP_PX = 14`（同一 viewBox 坐标系），则一次选中该位置上的全部 `run_id`。

失败运行不画成矩阵点、平行坐标折线或 3D 点。支配标签来自 `readBundle()` 对完整候选集合的分类。演示数据中，F（`3a-demo-run-f`）在 M–E 上被 G（`3a-demo-run-g`）支配，三维仍非支配；详情保留未舍入值，其中包括 `E=5.0925 J`。

## 3D 遮挡检查

在演示 bundle 的默认坐标域上，用 `projectRun()` 计算七个点的 viewBox 坐标。最近的一对是 C 与 D，距离约 44（测量值 43.8）。没有任何一对小于或等于 14，因此这七个演示点没有触发“同一投影位置”的合并选择。Node 测试断言每个演示点的 coincident 列表只包含它自己的 `run_id`。浏览器中这七个点也能分开看出，D、E、F、G 带有三维非支配标记。

完全重合时一次选中多个 `run_id`，只在测试构造的数据上检查过：`overlap-a` 与 `overlap-b` 的 M、E、L 相同，点击其中一个会同时选中这两个 `run_id`。那不是这七个演示点的结果。

## 检查证据

### Node 与 Python

实现完成后运行过：

```bash
node --test --test-concurrency=1 tests/3a.test.mjs tests/3a_startup.test.mjs tests/3b.test.mjs
python -m unittest discover -s tests -p "test_*.py"
```

当时 Node.js 为 v24.22.1。结果是 Node 15 项通过（原有 3A 测试 10 项，`tests/3b.test.mjs` 5 项），Python 8 项通过。这些测试使用模拟 DOM，不代替浏览器里的视觉检查。

`tests/3b.test.mjs` 覆盖的内容是：

- 矩阵有 9 个单元；反向 M–E 与正向 M–E 使用同一组二维标签；F 的悬停文字含原始 `E=5.0925`，并标为二维被支配、三维非支配。
- 只显示一个配置时，颜色仍按完整配置集合编码。筛选不改轴域、正式参照 ID 和 F 的二维标签。
- 失败运行不出现在矩阵单元中。
- 平行坐标与矩阵共用选择。能耗轴刷选可以只留下 A 和 B，且不把刷选范围写进共享状态，也不改轴域或标签。
- 固定 3D 投影中七个演示点互不落入 14 像素重叠阈值。点击 G 后矩阵高亮同一个 `run_id`。构造的重合点会同时返回两个 `run_id`。失败运行不画点。
- 页面只请求 `examples/3a-demo/bundle.json`，状态为 `fixture_only`，正式参照显示为「无」。矩阵点选 F 后，平行坐标和 3D 都高亮该运行。

### 浏览器

在 `http://127.0.0.1:8765/app/3b/index.html` 上实际操作过。下面这些结论来自浏览器，不来自模拟 DOM：

- 矩阵：在 M–E 单元点击 F，详情给出未舍入数值，M–E 被 G 支配，三维非支配。Shift 再点 G 后，选中为 `3a-demo-run-f` 与 `3a-demo-run-g`。取消 G 后可见数为 6/7，G 的点消失，F 的选择和六个坐标值不变。框选该单元得到全部 7 个 `run_id`。把一个坐标最小值改为 0.2 后，重置坐标回到 0.9113。清除选择后选中为「无」，显示全部后恢复 7/7。
- 桌面宽度下矩阵小图约 513px，点的可点区域约 14×14 CSS 像素，单元外标题约 15px，刻度可以读出。390px 窄窗口中矩阵保持 3×3 并可横向滚动，点约 8×8 CSS 像素，刻度约 7px。窄窗口更难点，这一步没有因此修改共享散点图组件。
- 平行坐标：点击 F 的有色折线后选中 `3a-demo-run-f`。能耗轴从最大值刷到 6.6 后只剩 A 和 B，坐标值不变，正式参照仍为「无」。取消 G 后 G 的折线消失。三条轴标题完整，分别为 `总完成时间 M (s) ↓`、`任务相关能耗 E (J) ↓`、`平均端到端延迟 L (s) ↓`。轴附近的窄条用于刷选。
- 3D：点击 F 后详情为 `3a-demo-run-f`，M–E 被 G 支配，三维非支配，坐标值不变。取消 G 后 3D 上的 G 消失，F 仍被选中。显示全部后为 7/7，清除选择后选中为「无」。图上可以分开看到各点；F 同时有三维非支配虚线圈和选择环。

## 限制

- 演示 bundle 不能当作调度算法比较或 RQ3 证据。
- 3B 三种视图之间可以高亮同一个 `run_id`。成员 A 当前的 3A 页面不会跟着高亮。
- 数据契约 `docs/data_contract.md` 仍是双人审查草案，本记录没有把它标成已会签。
- 本文没有比较三种编码的感知优劣，也没有受试者实验。
- 3D 的约 44 像素是 viewBox 坐标中的计算距离，用来和重叠阈值 14 比较。它不是浏览器把 SVG 缩放之后的 CSS 像素距离。
